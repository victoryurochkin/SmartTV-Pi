# Стриминг и пульт в браузере

С главного экрана Kodi выберите видеосервис. Пока работает Chromium, Kodi освобождает видеовыход. Клавиша F12 возвращает главный экран. Возврат также запускается при закрытии Chromium или сбое Cage. У каждого сервиса свой постоянный профиль с локальными данными, куки и авторизацией в `/data/home/.local/share/home-tv/browser/`.

## Каталог сервисов

Штатные плитки описаны в `/usr/share/home-tv/services.json`. Чтобы добавить или изменить сервис, скопируйте этот файл в `/data/config/services.json` и отредактируйте копию, либо воспользуйтесь локальной веб-панелью, когда она настроена. Пользовательский файл заменяет каталог целиком. Чтобы сохранить профиль сессии, оставьте идентификатор `id` неизменным. В списке допускается до 100 записей.

```json
{
  "services": [
    {
      "id": "youtube-web",
      "name": "YouTube в браузере",
      "url": "https://www.youtube.com/",
      "icon": "DefaultVideo.png",
      "user_agent": null,
      "flags": [],
      "zoom": 1.0,
      "prefer_h264": true,
      "quality_note": ""
    }
  ]
}
```

Обязательны `id`, `name` и `url`. Идентификатор содержит до 40 латинских букв нижнего регистра, цифр и дефисов и начинается с буквы или цифры. Ссылки используют HTTPS. `flags` принимает `spatial-navigation` для поддержки пространственной навигации Chromium и `autoplay` для разрешения автоматического воспроизведения. `zoom` устанавливает масштаб интерфейса и страницы при открытии, допустимый диапазон от 0.5 до 3.0. `quality_note` добавляют после измерения качества по [протоколу](test-report.md). По умолчанию используется штатный User-Agent Chromium.

Расширение Manifest V3 с `prefer_h264` ограничено доменами YouTube и предлагает AVC вместо VP8, VP9 и AV1, если плеер использует стандартные проверки браузера. Выбор потока зависит от сервиса. Widevine ставит штатный диспетчер компонентов Chromium, поэтому при первом запуске сервису с DRM могут понадобиться подключение к интернету, время на загрузку и повторное открытие. Состояние проверки приведено в [матрице совместимости](compat.md).

## Управление

| Вход | Домой | Режим стрелок или курсора |
| --- | --- | --- |
| Клавиатура | F12 | F9 переключает режим пульта. Обычные клавиши клавиатуры продолжают передаваться браузеру. |
| HDMI-CEC | Root Menu, если телевизор отправляет команду приставке | Синяя кнопка |
| ИК/Flirc | Home на распознанном пульте или F12 | Синяя кнопка или F9 |
| Веб-пульт | Главный экран | Кнопка переключения режима или тачпад |

В режиме курсора стрелки пульта перемещают указатель, OK выполняет щелчок. В режиме стрелок OK соответствует Enter. Изначально `youtube-tv` использует стрелки, остальные плитки открываются в режиме курсора. Для ввода с телефона поддерживаются печатные символы английской раскладки. Переключите активную раскладку приставки на английскую перед отправкой текста. Для кириллицы используйте физическую клавиатуру с нужной раскладкой или клавиатуру сайта, если сервис показывает её. Совместимость горячих клавиш, CEC и воспроизведения в Chromium на Pi помечена как **[НЕ ПРОВЕРЕНО НА УСТРОЙСТВЕ]**.

Для настройки ввода в Chromium создайте `/data/config/input.json`. `remote_devices` содержит фрагменты имён устройств из `evtest` или `/proc/bus/input/devices`. При открытии браузера совпавшие устройства передают свои кнопки через обработчик пульта. Не добавляйте сюда обычную клавиатуру. `cec_adapter` задаёт имя порта libCEC, например `/dev/cec0`. Если параметр опущен, обработчик пробует обнаруженные адаптеры. `cec_enabled` позволяет отключить CEC только в браузере. `keymap` связывает код evdev с действием `home`, `mode`, `ok` или `back`.

```json
{
  "cec_enabled": true,
  "cec_adapter": "/dev/cec0",
  "remote_devices": ["Flirc"],
  "keymap": {"KEY_RED": "home", "KEY_BLUE": "mode"}
}
```

При диагностике зависшей сессии с локальной консоли или через разрешённый SSH выполните `sudo systemctl start home-tv-kodi.service` и проверьте журнал командой `journalctl -u home-tv-browser.service -u home-tv-browser-input.service -u home-tv-session.service`. В штатном интерфейсе используются локальные команды `/usr/lib/home-tv/session open <id>` и `/usr/lib/home-tv/session home` от имени службы `hometv`.
